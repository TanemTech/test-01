# Общая публикация TANEM → Selectel

## Что это делает

Один раз устанавливается ограниченный приёмник на существующий сервер. Управляющий
репозиторий `TanemTech/test-01` подключает сайты из `deploy/sites/*.json`: выдаёт
каждому отдельный SSH-ключ, сохраняет его в GitHub Actions Secret этого сайта и
запускает проверку. После успешной проверки GitHub отправляет готовый статический
артефакт на Selectel. Опросов по таймеру нет.

`TanemTech` — личный аккаунт, поэтому секреты организации не используются.
Для автоматического добавления секретов в клиентские репозитории управляющий
репозиторий использует отдельный fine-grained token. Токен не получает права
изменять код, workflows, DNS, счета или настройки Selectel.

## Однократное подключение владельцем

1. В root web-консоли Selectel выполнить опубликованный `deploy/install.sh` из
   проверенного commit SHA. Он проверяет существующие Nginx/SSH и создаёт пользователя
   `tanem-publish`, root-owned приёмник, отдельные ключи и правило sudo только для
   приёмника. Не меняет SSH-конфигурацию, firewall, DNS, существующие сайты или таймер Марины.
   При успешной локальной проверке выводит `SETUP_OK` и одну JSON-строку.
2. В `TanemTech/test-01` → Settings → Secrets and variables → Actions создать
   `TANEM_SERVER`, значение — выведенная JSON-строка. Она содержит закрытый ключ:
   не публиковать и не пересылать её в чат. Ввести напрямую в GitHub Secrets.
3. Создать fine-grained personal access token для владельца `TanemTech`.
   Repository access: All repositories — для подключения будущих репозиториев
   без ручного изменения доступа. Права: **Actions: Read and write**,
   **Secrets: Read and write**, **Contents: Read-only** (Metadata добавляется автоматически).
   Сохранить его только в управляющем репозитории как `TANEM_GITHUB_TOKEN`.
   Срок действия выбирает владелец; при истечении заменить этот секрет.
   Для ограниченного пилота можно выбрать только `test-01`, но тогда новые
   репозитории понадобится добавлять в разрешения токена.
4. Actions → **Connect sites to Selectel** → Run workflow → main.
   Успешное подключение запускает Validate TANEM test site, затем Publish tested
   site to Selectel. Результат подтверждён только при `DEPLOYED` и
   `EXTERNAL_HTTP_OK` с одним и тем же commit SHA.

Пока без REG.RU: создаётся HTTP virtual host `test-01.tanem.ru`; проверка выполняется
по IP сервера с заголовком Host. Обычная ссылка по домену и HTTPS не обещаются до
отдельного подключения DNS/SSL. Автоматика не создаёт новый платный сервер.

## Следующий сайт: работа ChatGPT/технического специалиста

Работа только через GitHub, команд на сервере и ручного копирования секретов нет.

1. Проверить инструкцию AGENTS/DEPLOYMENT клиентского репозитория, его production-
   проверки и статический артефакт. Уточнить у владельца slug, если он не задан.
   Не назначать новый адрес клиенту самовольно.
2. Добавить `.github/workflows/selectel-site.yml` из шаблона в `deploy/templates/`.
   Указать точное имя workflow проверки, имя файла workflow, артефакт и проверенный
   commit SHA кода приёмника/клиента в управляющем репозитории.
3. Добавить запись `deploy/sites/<slug>.json` в управляющий репозиторий. Только
   после готовности workflow клиента. Commit в main запускает Connect sites.
4. Дождаться успешных CI и публикации. Проверить внешнюю выдачу того же SHA.
5. Для проверки обновления изменить тестовую страницу в main, дождаться нового
   успешного workflow и проверить новый SHA через внешний HTTP. Не ограничиваться
   сообщением «ключ подключён».

Для текущего salon-шаблона можно использовать уже существующий Pages-артефакт
`github-pages` (ZIP с `artifact.tar` внутри). Структуру и состав сайта не меняем;
приёмник принимает именно проверенный артефакт, не скачивает весь репозиторий.
Приватные репозитории поддерживаются при доступе токена к ним и доступности Actions.

## Существующие production-сайты

Марина продолжает работать по старой схеме. Другие существующие сайты не становятся
автоматически подключёнными от одной установки. Если hostname уже есть в Nginx,
приёмник откажется его перехватывать. Перевод существующего сайта требует отдельной
проверки текущего root, SSL, таймеров и аккуратной миграции; этот пакет не делает её
вслепую. Не запускать старый `ops/install-selectel-test.sh`.

## Границы и восстановление

- Это публикация готовых статических HTML/CSS/JS/медиа, не запуск произвольных серверных приложений.
- Сайты находятся только в `/srv/tanem-sites/<slug>`. Существующие `/var/www/*` не трогаются.
- Ключ клиента не даёт shell, port forwarding, регистрацию другого сайта или запись вне своего дерева.
- На сервере нет GitHub PAT и не исполняется код из артефакта.
- Нет искусственного лимита 150 МБ/числа фотографий из старого скрипта. Реальные пределы:
  свободное место сервера, тарифы и ограничения GitHub Actions. Нельзя обещать бесконечную ёмкость.
- Сначала распаковка во временную версию, затем атомарное переключение `current`.
  Поломанная распаковка не заменяет сайт. Ошибка Nginx/локального HTTP возвращает старую версию.
- Хранятся текущая и предыдущая версии. Для тяжёлого сайта на время обновления нужно
  место для новой версии, текущей и предыдущей. Сбой cleanup отмечается в журнале.
- Журнал незавершённой операции позволяет восстановить предыдущее состояние при
  следующем запуске публикации после аварийного прерывания. Это не замена внешнему backup.
- Nginx перечитывает конфигурацию только при первом размещении нового сайта. Изменения
  уже подключённого сайта переключают только ссылку на файлы.
- Внешняя HTTP-проверка после публикации выявляет проблемы доступа снаружи, но сама
  не откатывает работающую локальную версию при сетевом сбое.
- Гарантия «совсем без ошибок» невозможна. Реальную работу на Selectel подтверждает
  только сквозной запуск после добавления владельцем секретов.

## Проверки пакета

`python3 -m unittest discover -s deploy/tests -v`: некорректные архивы, traversal,
симлинки, чужой репозиторий, устаревшие сборки, сбои проверки, восстановление,
сохранение предыдущей версии и существующих настроек, Pages/ZIP-артефакты.

Workflow Publisher tests запускает полную установку и реальное SSH → Nginx HTTP
в одноразовой Ubuntu 24.04 VM GitHub. Создаёт два независимых сайта и обновляет первый.
Отдельный job проверяет доступность SSH Selectel из GitHub без входа и изменений.

`deploy/install.sh` воспроизводимо собирается `python3 deploy/build_installer.py`.
Публичный установщик не содержит паролей/ключей; ключ создаётся локально на сервере.
