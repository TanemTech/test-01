# Автоматическая первая ссылка

Исходные шаблоны сайтов не меняются. Их workflow `pages.yml` копируется в
клиентский репозиторий вместе с сайтом и его проверками.

ChatGPT создаёт в управляющем `TanemTech/test-01` файл
`deploy/pages/ИМЯ-РЕПОЗИТОРИЯ.json`:

```json
{"repository": "TanemTech/ИМЯ-РЕПОЗИТОРИЯ"}
```

Коммит в main автоматически включает Pages через API, запускает `pages.yml`
клиента и ждёт успешной публикации и доступности HTTPS. Готовая ссылка выводится
как `PAGES_READY` в журнале и в результате Actions. ChatGPT проверяет результат
запуска и передаёт ссылку специалисту. Дальнейшие правки сайта публикуются на этой
же ссылке обычным `push` в клиентский main.

Здесь нет подключения к Selectel, изменений DNS или публикации рабочего сайта.
Записи `deploy/pages/*.json` независимы от `deploy/sites/*.json`.
Создание произвольного пустого репозитория само по себе ничего не публикует.

## Однократный доступ владельца

Токен хранится только в Actions secret управляющего репозитория:
`TANEM_PAGES_TOKEN`. Для совместимости используется `TANEM_GITHUB_TOKEN`, если
отдельного Pages-токена нет. Он должен иметь доступ к нужным клиентским
репозиториям (All repositories включает будущие), права Contents: read,
Actions: write, Pages: write и Administration: write. Последнее требуется API
создания Pages. Не передавать токен в чат и не копировать его в клиентские сайты.

Если прав не хватает, подключение явно завершается ошибкой. После исправления
доступа можно повторить неудачный job либо изменить соответствующий JSON
(например, добавить `"retry": 1`). Ручной запуск workflow повторяет проверку всех
записей; обычный push обрабатывает только добавленные и изменённые записи.

До включения проверяется, что репозиторий активен, его основная ветка —
`main`, он содержит клиентский `pages.yml` и не является исходным COPY-шаблоном.
Поддерживаются публичные репозитории, а также приватные репозитории при наличии
подходящего тарифа GitHub. Для личного аккаунта GitHub Pages из приватного
репозитория доступен на GitHub Pro; также поддерживаются Team и Enterprise.
На GitHub Free исходный репозиторий для Pages должен быть публичным.

Если репозиторий приватный, но тариф или права токена не позволяют включить Pages,
автоматизация завершится явной ошибкой. Без отдельного разрешения ниже она **не меняет видимость репозитория**.
Для приватного репозитория с публичной Pages-страницей сам репозиторий остаётся
закрытым, но опубликованные HTML/CSS/JS и изображения доступны всем в интернете.
Перед публикацией нельзя оставлять в публикуемых файлах секреты или внутренние
материалы.

Также проверяется, что другие workflow не публикуют что-либо по завершении Pages.
Чужой существующий домен Pages не перенастраивается. Данные клиента должны уже
проходить проверки шаблона; успешная проверка с пропущенной публикацией не
считается готовой ссылкой.

Рабочий сайт на Selectel выпускается отдельно и только после разрешения.

## Публичные клиентские репозитории на GitHub Free

Новые клиентские репозитории создаются публичными через `repository_requests.py`.
Обычная заявка Pages не меняет видимость уже существующего репозитория.

Если владелец явно разрешил открыть существующий клиентский репозиторий,
сначала проверить все его ветки, теги, историю и материалы. После проверки в
его конкретную заявку `deploy/pages/<repository>.json` можно добавить
`public_visibility_reviewed_refs`: объект `полное имя Git ref → полный SHA`
для всех refs из GitHub API, включая refs pull request. Перед изменением
видимости автоматика сверяет полный набор refs; новое или изменённое состояние
останавливает операцию. Без этого поля приватный репозиторий остаётся приватным.
Не добавлять такое разрешение шаблонам или управляющему репозиторию.

Это однократный переход: после успешного открытия уже публичный репозиторий
обрабатывается обычным Pages pipeline. Токен остаётся только в управляющем
репозитории. Selectel, DNS и HTTPS production эта операция не запускает.
