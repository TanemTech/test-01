# Создание клиентских репозиториев TANEM из ChatGPT

Эта автоматизация независима от Pages и Selectel. Управляющий `TanemTech/test-01`
принимает GitHub Issue и создаёт новый **публичный** клиентский репозиторий через
GitHub API. Он не подключает Pages, не выдаёт SSL и не публикует на Selectel.

`TanemTech` — один общий личный аккаунт GitHub, подключённый ко всем проектам
ChatGPT технических специалистов. Префиксы `Sergei-` и `Ilya-` нужны только
для сортировки клиентских репозиториев, а не для разделения прав.

## Разовая настройка владельца

1. В `deploy/repository-creators.json` прописаны разрешённые ключи проектов
   ChatGPT (`sergei`, `ilya`) и их неизменяемые префиксы репозиториев.
   В инструкциях каждого проекта ChatGPT указать его ключ. Не давать модели
   выбирать ключ произвольно из названия клиента.
2. Создать отдельный fine-grained token для личного аккаунта `TanemTech`,
   разрешающий **создание репозиториев** (Repository creation: write).
   Не использовать секреты Pages/Selectel.
   Сохранить его в `TanemTech/test-01` → Actions secrets как
   `TANEM_REPO_CREATOR_TOKEN`. Не передавать токен в чат.
3. Проверить, что Issues в `test-01` включены и проекты ChatGPT используют
   подключённый общий аккаунт `TanemTech`. Разрешения на изменение управляющего
   репозитория техническим специалистам отдельно не выдавать.

**Ограничение:** GitHub видит заявки из всех проектов как действия одного
аккаунта `TanemTech`. Он не передаёт проверяемый идентификатор проекта ChatGPT.
Поэтому поле `project` — организационная метка из инструкции соответствующего
проекта, а не криптографически подтверждённая личность сотрудника. При ошибке
ChatGPT может указать чужую метку; это не даёт новых прав GitHub, но неверно
пометит репозиторий. Для строгого разграничения понадобятся отдельные учётные
записи/доверенные каналы.

## Что делает ChatGPT специалиста

1. Получает название клиента и **прямую** ссылку Яндекс.Карт.
2. Подготавливает латинский `client_slug` вида `anna-nails`.
3. Берёт фиксированное значение `project` из инструкции текущего проекта
   (`sergei` либо `ilya`) и через GitHub создаёт в `TanemTech/test-01` Issue:
   - Title (строго): `TANEM: CREATE REPOSITORY`
   - Body (строго JSON, без Markdown):
     `{"project":"sergei","client_slug":"anna-nails","yandex_url":"https://yandex.ru/maps/org/anna/123"}`
4. Дожидается ответа Actions в комментарии к Issue и передаёт специалисту
   **фактическую** ссылку на созданный репозиторий. Никогда не утверждает,
   что создание успешно, пока оно не подтверждено.

## Защита

- Только общий GitHub-аккаунт `TanemTech` может запросить создание; ключ проекта
  допускается только из утверждённого списка. Произвольный префикс запрещён.
- Имя репозитория собирается из префикса + валидированного `client_slug`.
- Ссылка должна быть `https://yandex.../maps`; длинные ссылки больше 300
  символов отклоняются без обрезания.
- Новый клиентский репозиторий создаётся публичным, с README и URL карты в описании,
  чтобы поддерживать бесплатный предпросмотр GitHub Pages на GitHub Free.
  Все файлы и история публичны: перед загрузкой проверить клиентские материалы,
  не добавлять пароли, ключи, cookies или непубличные данные.
  Это правило относится только к новым клиентским сайтам; существующие репозитории,
  шаблоны и управляющий репозиторий автоматически не открываются.
- Запрос никогда не меняет и не удаляет существующие репозитории. При занятом
  имени GitHub API отклоняет создание; специалист выбирает другое имя.
- Исполнение идёт только в контролируемом GitHub Actions, данные Issues
  не интерпретируются как команды.
- Для масштабирования и защиты от массовых заявок можно отдельно добавить
  квоты/ручную блокировку; текущая версия принимает заявки только от `TanemTech`.

## Проверка

Локально: `python3 -m unittest discover -s deploy/tests -p 'test_repository_requests.py' -v`.
Сквозная проверка: одна заявка из проекта Сергея, одна из проекта Ильи,
попытка с неизвестным ключом проекта, дубликат имени; затем проверить загрузку файлов. Новые
репозитории должны иметь ожидаемый префикс, описание и не запускать публикацию.
