# Создание клиентских репозиториев TANEM из ChatGPT

Эта автоматизация независима от Pages и Selectel. Управляющий `TanemTech/test-01`
принимает GitHub Issue и создаёт новый **частный** клиентский репозиторий через
GitHub API. Он не подключает Pages, не выдаёт SSL и не публикует на Selectel.

`TanemTech` — личный аккаунт GitHub, не организация. Для каждого специалиста
используется его собственный GitHub login и отдельное приглашение в репозиторий.

## Разовая настройка владельца

1. В `deploy/repository-creators.json` внести точные GitHub-логины специалистов
   (например, Сергея и Ильи), их фиксированные латинские префиксы и аккаунты,
   которым нужен доступ `push`. Никогда не определять владельца только по имени
   проекта ChatGPT или тексту заявки.
2. Создать отдельный fine-grained token для личного аккаунта `TanemTech`,
   разрешающий **создание репозиториев** и **Administration: write** для
   приглашения сотрудников. Не использовать секреты Pages/Selectel.
   Сохранить его в `TanemTech/test-01` → Actions secrets как
   `TANEM_REPO_CREATOR_TOKEN`. Не передавать токен в чат.
3. Проверить, что Issues в `test-01` включены. У специалистов должен быть
   собственный GitHub login и доступ к созданию Issues в публичном управляющем
   репозитории. Доступ к коду/секретам управляющего репозитория не давать.
4. Убедиться, что подключение GitHub в проекте ChatGPT специалиста работает
   под **его** аккаунтом. Если оба проекта пользуются общим `TanemTech` login,
   надёжно различить Сергея и Илью по Issue невозможно: не включать автосоздание.

## Что делает ChatGPT специалиста

1. Получает название клиента и **прямую** ссылку Яндекс.Карт.
2. Подготавливает латинский `client_slug` вида `anna-nails`.
3. Через GitHub создаёт в `TanemTech/test-01` Issue:
   - Title (строго): `TANEM: CREATE REPOSITORY`
   - Body (строго JSON, без Markdown):
     `{"client_slug":"anna-nails","yandex_url":"https://yandex.ru/maps/org/anna/123"}`
4. Дожидается ответа Actions в комментарии к Issue и передаёт специалисту
   **фактическую** ссылку на созданный репозиторий. Если нужно, сообщает о
   принятии приглашения GitHub. Никогда не утверждает, что создание успешно,
   пока оно не подтверждено.

## Защита

- Допускаются только GitHub-логины из списка; префикс нельзя задать заявкой.
- Имя репозитория собирается из префикса + валидированного `client_slug`.
- Ссылка должна быть `https://yandex.../maps`; длинные ссылки больше 300
  символов отклоняются без обрезания.
- Новый репозиторий создаётся приватным, с README и URL карты в описании.
  Перед включением публичных Pages проверить состав клиентских материалов.
- Запрос никогда не меняет и не удаляет существующие репозитории. При занятом
  имени GitHub API отклоняет создание; специалист выбирает другое имя.
- Исполнение идёт только в контролируемом GitHub Actions, данные Issues
  не интерпретируются как команды.
- Если приглашение не удалось, репозиторий остаётся созданным, а владельцу
  сообщается об ограничении доступа. Не создавать второй репозиторий.
- Для масштабирования и защиты от массовых заявок можно отдельно добавить
  квоты/ручную блокировку; текущая версия ограничивает круг инициаторов.

## Проверка

Локально: `python3 -m unittest discover -s deploy/tests -p 'test_repository_requests.py' -v`.
Сквозная проверка: одна заявка от Сергея, одна от Ильи, попытка от неизвестного
аккаунта, дубликат имени; затем проверить доступ к загрузке файлов. Новые
репозитории должны иметь ожидаемый префикс, описание и не запускать публикацию.
